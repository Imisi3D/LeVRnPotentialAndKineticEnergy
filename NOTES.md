# Repository notes

Cross-cutting conventions for this repo that are not obvious from the code.

## Why the .gitignore re-includes some .csproj/.sln files

This is a Unity project, and the `.gitignore` is the standard Unity one. It
ignores `*.csproj` and `*.sln` on purpose: Unity **regenerates** those from the
Assembly definitions every time the project is opened, so committing them would
mean constant churn and merge noise.

The upgrade work, however, adds **hand-authored** .NET projects that are NOT
generated by Unity and must be version controlled: the engine-agnostic C#
libraries under `src/` (for example `src/LeVRn.Tutor`, `src/LeVRn.Physics`,
`src/LeVRn.Progress`) and their headless test projects under `tests/`, plus the
solution `LeVRn.Tutor.sln` that ties them together.

To keep both true at once, the `.gitignore` re-includes exactly the
hand-authored files with these exceptions:

```
!/src/**/*.csproj
!/tests/**/*.csproj
!LeVRn.Tutor.sln
```

Why this shape:
- Unity only ever generates its `.csproj`/`.sln` at the **repo root** (for
  example `Assembly-CSharp.csproj` and a solution named after the project
  folder). Nothing generated lands under `src/` or `tests/`. So re-including all
  project files beneath those two directories is safe: it captures the
  hand-authored projects and cannot accidentally track a generated one.
- The globs are directory-scoped rather than a per-file allow-list, so **adding
  a new library or test project under `src/` or `tests/` needs no further
  `.gitignore` change**. (An earlier version listed each file by name, which had
  to be patched every time a task added a project. The globs remove that chore.)
- The solution stays a single explicit exception (`!LeVRn.Tutor.sln`) because it
  lives at the repo root, right where Unity's generated `.sln` would also appear.
  A blanket root `*.sln` re-include would wrongly track Unity's generated
  solution too. There is only ever one hand-authored solution, so this one line
  never needs to change.

### If you add a new project
- Under `src/` or `tests/`: nothing to do. Add the `.csproj` and it is tracked.
- A new **solution** file (rare): add another explicit `!YourName.sln` line, for
  the same reason the existing one is explicit.

### How to verify
`git check-ignore -v <path>` reports whether a path is ignored and by which
rule. A hand-authored project should print nothing (not ignored); a Unity
generated root file such as `Assembly-CSharp.csproj` should still report the
`*.csproj` rule (ignored). This was checked when the pattern was introduced.

## Build and test
- The repo has the .NET 8 runtime but no system SDK; a user-local SDK
  (`%USERPROFILE%\.dotnet`) is used. Run tests with
  `& "$env:USERPROFILE\.dotnet\dotnet.exe" test LeVRn.Tutor.sln`.
- The `src/` libraries target netstandard2.1 with no `UnityEngine` reference and
  no third-party packages, so they build and test headlessly and stay easy to
  drop into the Unity project later.
